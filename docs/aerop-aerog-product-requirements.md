# Aerop / Aerog 音色打包与播放需求说明

> 状态：根据产品口述与后续澄清整理（工作草案）  
> 适用范围：上位机音色工具 + 设备端播放/更新  
> 相关现状：当前引擎以 DBNK 流式采样为主；尚无 `.aerop` / `.aerog` 格式与 tech 激活矩阵

---

## 1. 目标与范围

### 1.1 要解决什么

把底层部件音色（`xdi` / `xdd`）通过上位机组合成可下发、可切换、可增量更新的产品音色包，并在设备上按 MIDI（Bank/Program、CC、连奏关系）正确选层与叠加播放；同时明确效果器作为整条音频链路的可用能力。

### 1.2 交付物

| 交付物 | 责任方 | 说明 |
| --- | --- | --- |
| `.aerop` | 上位机导出 / 设备解析播放 | 单个专用音色（乐器或鼓） |
| `.aerog` | 上位机打包 / 设备安装更新 | 多个 `.aerop` + 采样的音色库；支持 Bank(CC0)+Program 调用 |
| 全量 / 增量更新 | 上位机打补丁 + 设备安装 | 库级替换与差分更新 |
| 效果器链路 | 设备端（上位机可配） | 现有 20+ 效果器全部可用，重点在链路而非新算法 |

### 1.3 非目标（本文未覆盖或未定案）

- 完整 SFZ 播放器兼容
- 取代现有全部 DBNK 工具链的迁移计划（待产品确认并存或替换）
- 效果器新算法开发（产品口径：现有效果器全开可用）

## 2. 总体架构

```text
xdi（乐器部件） / xdd（鼓部件）
        │
        ▼  上位机组合、激活规则、mono/poly
   ┌─────────────┐
   │   .aerop    │  单个专用音色
   └─────────────┘
        │
        ▼  多个 aerop + Bank/Program + 采样打包
   ┌─────────────┐
   │   .aerog    │  音色库（含采样与音色）
   └─────────────┘
        │
        ▼  全量 / 增量下发
   设备：解析 → Bank/PC 选音色 → Note On 选 tech → 叠加播放 → FX 链路
```

## 3. 部件约定：xdi / xdd

| 类型 | 用途 | 在 aerop 中的约束 |
| --- | --- | --- |
| **xdi** | 乐器类部件音色 | 仅当 `ins_type=INS` 时可选用 |
| **xdd** | 鼓类部件音色 | 仅当 `ins_type=DRUM` 时可选用 |

### 3.1 已澄清

- 每个 tech 槽位里放的是 **xdi**（乐器场景）。
- 若多个 xdi 引用**相同 wav**，打包时可 **共享采样数据**，避免重复占空间。

### 3.2 待产品补齐（规格缺口）

- xdi / xdd 的正式文件格式、字段表、示例包。
- 与现有 DBNK / artic / region 的映射关系。
- 每个 tech **是否仅 1 个 xdi，还是可挂多个 xdi**。

## 4. `.aerop`：单个专用音色

上位机将部件组合成专用音色，后缀 **`.aerop`**。

### 4.1 `ins_type`

| 值 | 可选部件 | 复音策略 |
| --- | --- | --- |
| **INS** | 仅 xdi | 由 `play_type` 决定（poly / mono） |
| **DRUM** | 仅 xdd | **始终 poly** |

INS 与 DRUM 不可混挂。

### 4.2 INS 专用：`play_type`

| 值 | 行为 |
| --- | --- |
| **poly** | 同 MIDI 通道可同时存在多个发音 |
| **mono** | 同 MIDI 通道出现音符交叉时，新 Note 关闭旧 Note；交叉时间 **5ms** |

补充约定：

- wav 自身持续时间、以及与交叉相关的细节，**直接沿用 xdi 内已有设置**，`.aerop` 不再单独配置一套时长/交叉参数。
- 该 mono 5ms 机制与历史讨论中的「Legato Time 20–200ms + SampleStart」是否并存/取代，**仍待产品确认**。

### 4.3 INS 专用：组合槽位（9 个）

| 槽位 | 是否必选 |
| --- | --- |
| **normal** | **必选** |
| tech0 … tech7 | 可选 |

语义：

- `normal`：默认层。
- `tech0`–`tech7`：技法/条件层；每个槽对应一组 xdi（部件组合）。

### 4.4 tech 激活模型

#### 4.4.1 激活选项池（共 12 项）

分类仅方便上位机 UI 展示，**不是互斥类别**。

**MIDI CC 类（值 > 64 视为激活；CC 为 7bit，0–127）：**

- CC21、CC22、CC23、CC24、CC25、CC26、CC27、CC28、CC64

**演奏类：**

| 选项 | 含义 |
| --- | --- |
| `legato` | 必须存在音符交叉（旧音未结束时出现新 Note On） |
| `lg_up` | 音符交叉，且新 note number **大于** 旧 note number |
| `lg_dn` | 音符交叉，且新 note number **小于** 旧 note number |

#### 4.4.2 每个 tech 的两个激活槽位

- 每个 tech 有 **2 个激活槽位**。
- 两个槽位共用上述 **12 个选项**。
- **某个选项一旦被槽位 A 选中，槽位 B 不能再选同一选项**（选项占用，非“类别互斥”）。
- 槽位可：
  - 只填 1 个 → 单条件；
  - 填 2 个 → **条件为 A AND B**；
  - **仅支持 AND，不支持 OR**。
- 两个槽是否允许全空、全空语义（非法 / 恒激活）→ **待确认**。

#### 4.4.3 判定时机（已澄清）

- 在 **Note On 发生时**，根据**当时**的激活状态，决定本发 Note On 使用哪些层。
- CC 在音符进行中途变化，**不回溯改变已发声层**；只影响**之后**的 Note On。

示例（tech1 绑定 CC21）：

1. CC21 ≤ 64 → 之后的 Note On 走 **normal**（假设无其他 tech 命中）。
2. 将 CC21 置为 > 64 并保持 → 之后的 Note On 走 **tech1**。
3. 中间是否 Note Off 不影响上述“状态保持”逻辑；关键是 **下一发 Note On 当时的条件**。

#### 4.4.4 多 tech 同时命中（已澄清）

- 多个 tech 条件同时满足时：**同时触发**，**叠加播放**各自对应的 wav / xdi 发音。
- **normal 在多 tech 命中时是否仍播放** → **待确认**（见第 8 章）。

#### 4.4.5 叠加播放的隐含运行时行为（待确认）

建议产品补齐：

- 一次 Note On 命中 N 个 tech → 是否开启 N 条 voice；
- 对应 Note Off / mono 切音是否 **成组关闭**；
- 多路叠加是否需要增益补偿（避免越叠越响）。

### 4.5 DRUM 行为（部分待确认）

已定：

- `ins_type=DRUM` 时只能选 xdd；
- 始终 poly。

待确认：

- DRUM 是否也有 normal/tech 槽与激活矩阵，还是单层无 tech。

## 5. `.aerog`：音色库打包

上位机将多个 `.aerop` 打包为 **`.aerog`**。

### 5.1 内容要求

- 打包文件须 **包含采样与音色文件**（自包含，不只写外部路径索引）。
- 相同 wav 跨 aerop / 跨 xdi 应可去重共享（与第 3 章一致）。

### 5.2 MIDI 调用

每个 aerop 在库内可配置：

| 字段 | 约定 |
| --- | --- |
| Bank | **仅使用 CC0**（不需要 CC32） |
| Program | Program Change |

范围：

- CC0、Program 均为 **0–127**；
- 上位机写入 UI **本身限制在 0–127**，不允许超限输入。

调用流程：

```text
CC0 = bank
Program Change = 选中该 bank 下对应 aerop
之后 Note/CC 按该 aerop 规则播放
```

### 5.3 更新方式

须支持：

1. **全量更新**：整库替换；
2. **增量更新**：只更新变化部分。

待确认：

- 增量最小单位（整个 aerop / 单个采样文件 / 二进制块）；
- 校验方式（hash、版本号）；
- 失败是否回滚到旧库。

## 6. 设备端播放逻辑（归纳）

### 6.1 选音色

1. 接收 CC0、Program Change；
2. 在已安装 `.aerog` 中定位对应 `.aerop`；
3. 加载/激活该音色的槽位与规则。

### 6.2 Note On 分派（INS）

```text
Note On (ch, note, vel)
  │
  ├─ 读取当前 CC21..28、CC64 状态（>64 = on）
  ├─ 判断是否与通道上旧音构成交叉，以及 up/dn
  ├─ 对 tech0..tech7：若其激活表达式为真 → 加入命中集合
  │
  ├─ 若命中集合非空：
  │     叠加触发各命中 tech 的 xdi/wav
  │     （normal 是否同播：待确认）
  └─ 若命中集合为空：
        使用 normal

  若 play_type=mono 且存在交叉：
        旧音与新音 5ms 交叉后关闭旧音
```

### 6.3 Note Off

- poly：按标准 MIDI 关对应 note（叠加层是否成组关：待确认）。
- mono：通常由新 Note On 触发旧音关闭；单独 Note Off 行为需与 xdi 一致。

## 7. 效果器与总链路

### 7.1 产品口径

- 效果器需求**更侧重链路（routing / chain）**，不是再开一批新算法。
- **当前 20 多个效果器全部可用**。

### 7.2 总链路（产品框图，已给出）

```text
USB MIDI / BLE MIDI / 内部 MIDI
            │
            ▼
     ┌──────────────┐
     │  MIDI 分通道  │   每通道音色均为 .aero（.aerop）
     └──────────────┘
        │         │         │
        ▼         ▼         ▼
   通道组 A    通道组 B    通道组 C
   0-5,7,14   6,8-13      15
        │         │         │
      GAIN      GAIN      GAIN
        │         │         │
        ▼         ▼         ▼
   立体声FX A  立体声FX B  立体声直通
   (5 可启用槽) (固定3级)   (无效果)
        │         │         │
      GAIN      GAIN      GAIN
        │         │         │
        └────┬────┴────┬────┘
             ▼
        立体声混音
             │
     ┌───────┼───────┐
     ▼       ▼       ▼
   GAIN    GAIN    GAIN
     │       │       │
   耳机    音腔   Line Out
```

#### 7.2.1 MIDI 入口

- 输入源：USB MIDI、BLE MIDI、内部 MIDI。
- 进入统一 MIDI 处理后，按 **MIDI 通道** 分流。
- 产品标注：**每个通道的音色均为 `.aero`**（与本文 `.aerop` 同义，命名待统一）。

#### 7.2.2 三路通道组（总线级，不是每通道一条独立 FX）

| 总线 | MIDI 通道 | 效果策略 |
| --- | --- | --- |
| **A（自由立体声 FX）** | 0、1、2、3、4、5、7、14 | 除 **3band comp** 外的所有效果；**五个槽位可同时启用** |
| **B（固定后处理）** | 6、8、9、10、11、12、13 | 固定顺序：**3band comp → EQ → Reverb**；初始均 **bypass** |
| **C（直通）** | 15 | **立体声直通**，不加效果 |

每条总线：进入 FX 前有一级 **GAIN**，离开 FX 后再有一级 **GAIN**，再进入总混音。

#### 7.2.3 输出

立体声混音后，分三路独立 **GAIN**：

1. 耳机  
2. 音腔  
3. Line Out  

### 7.3 由框图可直接落地的含义

1. FX 是 **按通道组总线** 处理，不是每个 MIDI 通道各挂一套完整链。  
2. 组 A 是“吉他/主奏类可编排 FX”（5 槽，禁 3band comp）。  
3. 组 B 是“固定母带感后处理”（压限→EQ→空间），默认全 bypass，可逐级打开。  
4. 通道 15 专供干声/直通（监听、节拍器、对齐参考等场景需产品确认用途）。  
5. 耳机 / 音腔 / Line Out 只做输出增益分流，不再各挂一套 FX。

### 7.4 仍待产品确认（总链路）

| # | 问题 |
| --- | --- |
| L1 | `.aero` 与 `.aerop` 是否同一文件？ |
| L2 | 组 A 五个槽：槽内可选 FX 的完整白名单？槽顺序是否可变？同一种 FX 能否占多槽？ |
| L3 | 组 A“可同时启用五个”：是最多 5 个并行/串联模块，还是 5 个固定槽位？串还是并？ |
| L4 | 组 B 的 3band/EQ/Reverb 参数存在全局还是跟 aerog/场景？ |
| L5 | 通道 15 的产品用途（干出、节拍、导奏、外部返送）？ |
| L6 | 进入组总线前，同组多通道是先按通道渲染再 sum，还是 voice 混完再进组 FX？ |
| L7 | 各组 GAIN（FX 前/后 + 三路输出）的默认值、调参入口（MIDI CC / 上位机）？ |
| L8 | 立体声：引擎现多为 mono 采样源时，如何生成组 A/B 的立体声（双单声道复制 / 真立体声 FX）？ |
| L9 | “除 3band 外所有”清单是否包含当前工程里未接线/ stub 的模块？ |

## 10. 工作量拆分

> 说明：按模块拆分技术工作，不估日历天。难度用侵入性与依赖风险描述。

### 10.1 总览

| 工作包 | 主要内容 | 侵入性 | 依赖风险 |

| W3 上位机打包器 | 采样去重、导出 aerop/aerog | 中 | 中 |
| W4 设备解析与库管理 | 安装、索引、Bank/PC 切换 | 中高 | 中 |

### 10.2 W1 — 格式与协议规格

- 定义 `.aerop` 头：`ins_type`、`play_type`、槽位表、每 tech 的 2 激活槽、xdi/xdd 引用。
- 定义 `.aerog` 头：aerop 目录、CC0 bank、program、采样表、去重索引、版本号。
- 定义增量包格式（待产品粒度）。
- 输出：正式规格文档 + 示例最小包（1 个 INS aerop + 1 个 DRUM aerop + 1 个 aerog）。

### 10.3 W2 — 上位机：音色编辑

- 工程 UI：`ins_type` 切换；INS 显示 play_type + 9 槽；DRUM 隐藏非法项。
- 槽位编辑：选择 xdi/xdd；normal 必填校验。
- 激活矩阵 UI：12 选项池、两槽占用互斥、AND 展示。
- （建议）矩阵仿真：给定 CC/连奏状态，高亮将触发的 tech。

### 10.4 W3 — 上位机：打包导出

- 扫描引用采样，按 hash/路径去重写入包内。
- 导出单个 `.aerop`。
- 多 aerop 编排 Bank/Program，导出 `.aerog`（含采样）。
- 导出前校验：normal 存在、选项不冲突、bank/pc 不重复、引用完整。

### 10.5 W4 — 设备：库安装与选择

- 存储布局（SD/Flash）：aerog 安装目录、索引缓存。
- 启动/热切换：按 CC0+PC 定位 aerop。
- 与现有 MIDI 接收路径对接（避免与旧 instrument 映射冲突）。

### 10.6 W5 — 设备：播放核心（最大块）

- Note On 前/时收集激活状态（CC 位图 + 交叉/音程方向）。
- tech 表达式求值（1 条件或 AND）。
- 多 tech 叠加触发；voice 分配与（待定）成组 Note Off。
- INS mono：5ms 交叉关旧音；复用/对齐 xdi 时长语义。
- DRUM：poly 路径；按最终确认接或不接 tech。
- 性能：多 tech 叠加对 64 voice / SD 带宽的预算与上限策略。

### 10.7 W6 — 全量 / 增量更新

- 全量：替换库、切换活跃版本。
- 增量：按确认粒度打补丁、应用、校验。
- 失败回滚、断电安全（至少保留上一可用版本）。
- 上位机侧补丁生成；设备侧应用器与进度/错误码。

### 10.8 W7 — 效果器链路

- 按产品总链路实现 **三总线**：组 A（5 槽自由立体声 FX，禁 3band）、组 B（固定 3band→EQ→Reverb，默认 bypass）、组 C（直通）。
- MIDI 通道映射到三组；组内多通道先混合再进组 FX（具体 sum 点待 L6 确认）。
- 组前/组后 GAIN + 混音后耳机/音腔/Line Out 三路独立 GAIN。
- 盘点“除 3band 外所有”模块清单与当前可调用状态；补齐未接线/stub。
- 立体声路径与现有 mono 采样源的衔接策略。
